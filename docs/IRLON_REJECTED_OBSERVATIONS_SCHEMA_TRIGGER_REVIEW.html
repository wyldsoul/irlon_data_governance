IRLON Rejected Observations
Schema & Trigger Architecture Review

Current non-production status review of the generic registry and source-specific enforcement modules for active IRLON instrument families.

Non-production implementation review — not deployed to production

Purpose

A deliberate rejection makes the affected public parameter value NULL; it does not delete or NULL the private/raw observation. The central registry records why the public parameter was suppressed, including the applicable QC rollup and audit metadata. Active records prevent later ingestion or replay from silently restoring that rejected value. Suppression is parameter-level, not whole-row deletion.

2. Active rejection identity and uniqueness

Only active records participate in uniqueness, so a reinstated decision remains in history without blocking a later active decision. For unique-source-row modules, identity is the source observation and parameter:

Active rejection identity

source_table, source_row_id, public_parameter.

Station/time and public mapping remain audit/enforcement context. Serial is nullable provenance, not identity.

CREATE UNIQUE INDEX rejected_observations_active_source_row_parameter_key
ON rejected_observations
  (source_table, source_row_id, public_parameter)
WHERE active AND source_row_id IS NOT NULL;

7. Trigger readiness

Each implemented module uses a BEFORE public-write guard and an AFTER private-write replay trigger. Private/raw data are preserved; only rejected public parameters are set to NULL with their stored QARTOD flag.

Staging hold point
SUNA is private-first. SeaFET and Aquadopp require approved private-first writer reordering and restored-production-clone archive validation before trigger activation.

8. SUNA archive-gate finding

The production-derived archive gate uses suna_ascii_process_recurring_final.R; the current writer identifies itself as suna_ascii_tscorrection_recurring_final.R. The mismatch remains unresolved and must be reviewed on a restored-production clone.

SBE37 functions and trigger wiring

sbe37_public_station() and sbe37_source_station() map _SITE_SBE37 ↔ SITE-WQ. The rejection API records the private row_id; serial is nullable provenance. A temperature rejection creates linked SBE37 salinity/DO children and, only when a matching private SeaFET row exists, a SeaFET pH child. Each inherits the same QARTOD flag.

CREATE TRIGGER sbe37_guard_rejected_public_parameters
BEFORE INSERT OR UPDATE ON seabird_sbeeco
FOR EACH ROW EXECUTE FUNCTION sbe37_guard_public_parameter_write();

CREATE TRIGGER sbe37_reapply_rejected_public_parameters
AFTER INSERT OR UPDATE ON seabird_sbe37
FOR EACH ROW EXECUTE FUNCTION sbe37_reapply_rejections_after_private_write();

9. Current SBE37 trigger example

Public write guard

sbe37_guard_rejected_public_parameters
BEFORE INSERT OR UPDATE on seabird_sbeeco

Runs through sbe37_guard_public_parameter_write() for the SBE37/ECO public path. It returns immediately when no active SBE37 rejection applies. Otherwise it derives the mapped private station and confirms the unique seabird_sbe37 source observation exists at that timestamp.

Matching rejected parameter(s) are forced to NULL and their paired public QC column receives the stored qc_flag. Missing, mismatched, or fabricated identity fails closed; unrelated parameters remain writable.

Private replay reapplication

sbe37_reapply_rejected_public_parameters
AFTER INSERT OR UPDATE on seabird_sbe37

Runs through sbe37_reapply_rejections_after_private_write(). It does nothing when no exact active SBE37 rejection exists. For a match, it re-applies NULL + stored QC suppression to the mapped public parameter(s).

It never NULLs or deletes private/raw SBE37 data.
